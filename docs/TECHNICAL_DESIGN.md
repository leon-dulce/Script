# 指定窗口脚本录制工具｜MVP 技术方案

## 一、目标与范围

本方案落实[产品设计文档](PRODUCT_DESIGN.md)中的 Windows 桌面 MVP：选择一个前台窗口，录制并编辑固定步骤，保存到本机，再通过快捷键执行或停止。目标是先完成可验证的端到端流程，不追求对所有应用的通用自动化能力。

## 二、推荐技术路线

| 层次 | 选择 | 原因 |
| --- | --- | --- |
| 桌面宿主 | C#、.NET 10 LTS、WPF | 适合 Windows 桌面应用，便于管理窗口、消息循环和后台任务。 |
| 界面 | WebView2 加 HTML/CSS/JavaScript | 可沿用现有 HTML Demo 的视觉设计，由桌面宿主提供系统功能。 |
| 系统能力 | Windows Win32 API，通过 C# 调用 | 负责窗口识别、键鼠事件、全局快捷键与模拟输入。 |
| 脚本存储 | 本地 JSON 文件 | 便于检查、编辑和添加版本号；MVP 不需要数据库或云端。 |

现有 [HTML Demo](../index.html) 是交互原型，其模拟录制与浏览器本地存储不应直接作为正式实现。正式版由界面向桌面宿主发送明确的操作请求，再由宿主把状态和步骤回传给界面。WebView2 只加载应用自带的本地页面，不向页面开放任意文件或系统调用。

## 三、核心模块

### 1. 窗口管理

- 在录制页面按快捷键时读取当前前台窗口，验证可用后确认录制目标；在执行页面按快捷键时根据已选脚本验证前台窗口并确认执行目标。用户无需先用鼠标从窗口清单选择目标。
- 运行时保存窗口句柄与进程标识，并在每次录制、回放前确认它仍指向原窗口；脚本文件只保存可用于重新选择窗口的程序信息和标题提示，不持久化窗口句柄。
- 录制点击时把屏幕坐标换算成目标窗口内容区坐标。回放时反向换算，因此窗口移动后仍可使用；内容区尺寸改变时先停止并提示重新录制或调整步骤。

### 2. 录制器

- 仅在录制状态启用键盘和鼠标监听。回调只收集事件并快速返回，步骤整理放在后台队列处理。
- 只接受目标窗口位于前台时发生的事件；过滤执行快捷键和程序自身注入的输入，避免录入控制键或重复事件。
- 将点击、双击、滚轮、按键、组合键以及相邻步骤的间隔整理为脚本步骤。录制暂停时不保存任何输入。
- 第一版把中文等输入法文字作为可手动添加或编辑的“输入文字”步骤；不保证仅凭物理按键事件还原输入法最终文字。

### 3. 快捷键与执行器

- 用 Windows 全局快捷键机制注册用户选择的按键；默认 F10，注册失败时要求换键。F12 为系统保留键，不提供为正式版全局快捷键。
- 快捷键根据当前工作页面分派：录制页面待机时开始一份新的录制，录制时结束并自动保存；执行页面待机时启动已选的已保存脚本，执行时停止。录制页面不根据已有步骤数量切换为回放。暂停录制后按快捷键只可在原目标窗口恢复；执行线程使用可取消任务，不能并行启动第二次。
- 界面上的开始录制或开始执行按钮可先进入等待目标窗口状态，用户切到目标窗口后自动确认启动，无需再次按快捷键。前台窗口无效，或执行目标的程序、内容区尺寸与脚本不匹配时，显示原因并保持停止状态。
- 执行方案随脚本保存，模式为单次、指定次数或持续执行。整段脚本完成一轮后按设定间隔等待，再决定是否开始下一轮；取消信号在步骤前、等待期间和发送输入前检查。
- 每一步执行前检查目标窗口是否存在、身份是否匹配且处于前台，再按保存的时间间隔发送模拟输入。停止、窗口失焦、关闭或尺寸变化时立即取消剩余步骤，并释放仍处于按下状态的按键。
- 不自动强行切换窗口，不尝试向后台窗口或权限高于本程序的窗口发送操作。

### 4. 状态与脚本存储

内部状态限定为：`待机 → 录制 → 暂停/待机`，以及 `待机 → 执行 → 待机`。界面只显示宿主确认后的状态，避免按钮显示与实际录制或执行状态不一致。

录制页面提供快捷键设置、开始及结束录制和步骤编辑，不提供手动新建、重新载入或保存按钮。每次开始新录制分配新的脚本编号；结束录制后，以目标窗口和录制时间生成名称，并自动保存非空脚本。没有步骤时不建立空脚本，后续步骤编辑自动保存当前脚本。新一轮录制保留之前已保存的脚本。

脚本库只在执行页面显示，并列出全部已保存脚本。执行页面提供执行方案与快捷键设置，修改后自动保存；不显示未命名、未保存标签或手动保存设置按钮。载入其他脚本时清除旧窗口句柄；用户切到目标窗口按快捷键重新确认，检查所属程序及内容区尺寸符合脚本后才可回放。

执行页面显示只读步骤列表。宿主持续回传执行步骤编号、动作、轮次、等待下一轮及等待目标窗口状态，界面据此高亮当前执行步骤并更新进度；停止或完成后清除执行中的高亮。执行时不允许修改步骤或切换脚本。

脚本采用带版本号的 JSON。字段至少包括唯一编号、脚本名称、目标程序提示、快捷键、执行方案、窗口内容区尺寸和步骤列表。步骤以明确类型保存，例如点击坐标、滚动量、按键组合、文本内容和等待毫秒数；加载时验证字段与数值范围。每个脚本使用编号命名的独立文件，保存时先写临时文件，再替换旧文件，避免中途退出损坏脚本。旧版单一文件在首次运行时迁移。脚本文件只允许数据步骤，不执行任意代码。

脚本内容以本地文件保存，MVP 不承诺对文本内容加密。界面须提醒用户暂停录制敏感输入，并检查已录制步骤。

## 四、实现顺序

1. **桌面框架**：把 HTML Demo 放入 WebView2，打通界面与宿主的消息和状态更新。
2. **窗口与快捷键**：完成目标窗口选择、前台判断、快捷键注册与冲突提示。
3. **录制与回放**：先支持点击、按键、滚轮和等待时间，再加入暂停、停止和失焦保护。
4. **编辑与保存**：完成步骤列表编辑、结束录制自动保存、编辑自动保存、多脚本库、JSON 读写及迁移。
5. **执行工作区**：完成每脚本的执行方式、次数、轮次间隔与快捷键自动保存，以及只读步骤列表和执行高亮。
6. **打包与验收**：生成 Windows 独立执行档，检查 WebView2 Runtime 是否可用。

## 五、验证标准

- **自动测试**：覆盖脚本库读写与迁移、非空录制自动保存及新录制不覆盖旧脚本、步骤与执行设置自动保存、按页面分派快捷键、执行方案校验、三种循环模式、事件到步骤的转换、状态切换、步骤高亮和停止规则。
- **桌面验收**：在实际 Windows 的普通测试窗口，通过快捷键确认前台窗口、开始与结束录制，验证自动保存后再次录制会新增脚本；重启工具并在执行页面切换脚本，验证三种执行模式、实时步骤高亮、轮次进度及快捷键停止。仅编译或启动成功不算功能验证通过。
- **异常验收**：验证空录制不保存、自动保存失败反馈、目标程序或尺寸不符、窗口失焦、窗口关闭、尺寸变化、快捷键冲突、脚本损坏及回放中停止。未完成的实际 Windows 操作测试必须明确记录，不得视为验收通过。
- **兼容性检查**：检查不同缩放比例与多显示器下的坐标；分别验证普通按键、组合键和手动文本步骤。

## 六、已知限制与后续方向

坐标步骤依赖窗口内容布局，界面变化后可能需要重新录制。Windows 模拟输入受权限级别限制，因此管理员权限窗口不纳入 MVP。后续可评估 UI Automation 控件定位、中文输入自动识别和条件执行。
