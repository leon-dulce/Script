# 指定窗口脚本录制工具｜MVP 技术方案

## 一、目标与范围

本方案落实[产品设计文档](PRODUCT_DESIGN.md)中的 Windows 桌面 MVP：设置录制快捷键，录制并编辑固定步骤，命名确认后保存到本机，再通过快捷键执行或停止。目标是先完成可验证的端到端流程，不追求对所有应用的通用自动化能力。

## 二、推荐技术路线

| 层次 | 选择 | 原因 |
| --- | --- | --- |
| 桌面宿主 | C#、.NET 10 LTS、WPF | 适合 Windows 桌面应用，便于管理窗口、消息循环和后台任务。 |
| 界面 | WebView2 加 HTML/CSS/JavaScript | 可沿用现有 HTML Demo 的视觉设计，由桌面宿主提供系统功能。 |
| 系统能力 | Windows Win32 API，通过 C# 调用 | 负责窗口识别、键鼠事件、全局快捷键与模拟输入。 |
| 脚本存储 | 本地 JSON 文件 | 便于检查、编辑和添加版本号；MVP 不需要数据库或云端。 |

现有 [HTML Demo](../index.html) 是交互原型，其模拟录制与浏览器本地存储不应直接作为正式实现。正式版由界面向桌面宿主发送明确的操作请求，再由宿主把状态和步骤回传给界面。WebView2 只加载应用自带的本地页面，不向页面开放任意文件或系统调用。

## 三、核心模块

### 1. 窗口管理

- 录制页面不选择或绑定窗口。全局快捷键或录制按钮直接启动键盘监听；执行页面仍确认前台窗口作为本轮目标。
- 运行时保存窗口句柄与进程标识，并在每次回放前确认它仍指向原窗口；脚本文件只保存可用于重新选择窗口的程序信息和标题提示，不持久化窗口句柄。
- 旧脚本的坐标步骤使用目标窗口内容区坐标。回放时反向换算，因此窗口移动后仍可使用；内容区尺寸改变时先停止并提示重新录制或调整步骤。

### 2. 录制器

- 仅在录制状态启用独立 STA 线程的键盘监听与消息循环，不启用鼠标监听。回调只收集事件与单调时间戳，通过并发队列交给界面每 100 毫秒取出并发布；切换焦点、最小化或界面繁忙不会阻塞监听。停止时先卸载监听并等待线程退出，再排空队列。
- 模拟回放输入标记 `ReplayInputTag`，只排除带该标记的注入输入与当前控制快捷键。其他软件转送的键盘事件继续记录，避免遗漏重映射或辅助输入。
- 接受任意前台窗口的键盘事件，窗口切换、关闭或尺寸变化不暂停录制；过滤当前配置的控制快捷键和FlowKey 自己回放的输入。其他功能键、左右修饰键、首次按下与松开均保留为独立事件，长按产生的重复按下不新增步骤，不把修饰键折叠到后续按键中。每次录制独立维护已按住键集合；松开后可再次记录按下，多键互不影响。过滤事件不更新录制时钟，松开步骤保留完整按住时间。
- 键盘步骤带有 `KeyAction`：新录制保存单键 `Down` 或 `Up`；旧脚本缺少该字段时默认 `Press`，仍按完整组合键按下再释放处理。`Press` 最多包含 5 个虚拟键，`Down` 和 `Up` 必须只有 1 个键。加载时校验动作枚举、键值与当前控制快捷键，防止回放触发自身快捷键。
- 将键盘事件整理为脚本步骤，实时发布每个动作及其旁边的间隔时间。记录时使用单调时钟，开始录制时间作为第一个事件的基准，后续延迟按相邻事件计算；等待毫秒数范围为 0–2147483647，不截断为 60 秒。停止前先处理已排队的有效事件。
- 不提供添加文字步骤；旧文字步骤仍可编辑和回放。不保证仅凭物理按键还原输入法最终文字。

### 3. 快捷键与执行器

- 用 Windows 全局快捷键机制注册用户选择的按键；默认 F10，注册失败时要求换键。F12 为系统保留键，不提供为正式版全局快捷键。
- 快捷键根据当前工作页面分派：录制页面待机时开始一份新的录制，录制时结束并打开命名窗口；执行页面待机时启动已选的已保存脚本，执行时停止。录制页面不根据已有步骤数量切换为回放，提供开始／停止录制按钮。执行线程使用可取消任务，不能并行启动第二次。
- 执行页面的开始执行按钮可先进入等待目标窗口状态，用户切到目标窗口后自动确认启动，无需再次按快捷键。前台窗口无效，或旧脚本的执行目标程序、尺寸不匹配时，显示原因并保持停止状态。
- 执行方案随脚本保存，模式为单次、指定次数或持续执行。整段脚本完成一轮后按设定间隔等待，再决定是否开始下一轮；取消信号在步骤前、等待期间和发送输入前检查。
- 每一步执行前检查目标窗口是否存在、身份是否匹配且处于前台，再按保存的时间间隔发送模拟输入。停止、窗口失焦、关闭或尺寸变化时立即取消剩余步骤，并释放仍处于按下状态的按键。
- 键盘回放按 `Down`、`Up` 或旧版 `Press` 发送输入并追踪仍按下的键；右 Ctrl/Alt、导航键等扩展键使用相应的 Win32 输入旗标，文本输入仍使用 Unicode 旗标。
- 回放不自动切换目标窗口，不向后台窗口或权限高于本程序的窗口发送操作；发布执行档默认请求管理员权限；录制结束时前置主界面以显示命名对话框。

### 4. 状态与脚本存储

内部运行状态限定为：`待机 → 录制 → 待机`，以及 `待机 → 执行 → 待机`；另用待命名状态保留已停止但尚未确认保存的录制。界面只显示宿主确认后的状态，避免界面显示与实际录制或执行状态不一致。

录制页面提供快捷键、开始／停止按钮和步骤编辑，不提供目标窗口、添加文字、手动新建、重新载入或保存按钮。每次开始新录制分配新的脚本编号；结束非空录制后立即打开名称对话框。宿主验证名称修剪后为 1–100 个字符，确认且写入成功后切换到执行页面并选中该脚本。没有步骤时不建立空脚本、不弹出命名窗口。已命名脚本的后续步骤编辑自动保存，新一轮录制保留之前已保存的脚本。

名称无效或磁盘写入失败时，保持同一份待保存步骤、脚本编号和命名窗口，显示错误供重试。命名期间阻止切换工作区、开始新录制或直接关闭程序，以免静默丢失内容；放弃录制要求明确确认。按 Esc 不关闭命名窗口。

脚本库只在执行页面显示，并列出全部已保存脚本。执行页面提供执行方案与快捷键设置，修改后自动保存；不显示未命名、未保存标签或手动保存设置按钮。载入其他脚本时清除旧窗口句柄；用户切到目标窗口按快捷键重新确认，旧脚本检查所属程序及尺寸后才可回放；新全域键盘脚本不依赖录制窗口。

执行页面显示只读步骤列表。宿主持续回传执行步骤编号、动作、轮次、等待下一轮及等待目标窗口状态，界面据此高亮当前执行步骤并更新进度；停止或完成后清除执行中的高亮。执行时不允许修改步骤或切换脚本。

脚本采用带版本号的 JSON。字段至少包括唯一编号、脚本名称、目标程序提示、快捷键、执行方案、窗口内容区尺寸和步骤列表。步骤以明确类型保存，例如点击坐标、滚动量、按键及其 `KeyAction`、文本内容和等待毫秒数；加载时验证字段与数值范围。新增可选的 `KeyAction` 字段保持旧文件可读。`GlobalKeyboardRecording` 标记新录制，默认 false 兼容旧脚本；true 时录制目标信息留空、尺寸为 0，禁止坐标步骤，回放启动时不比较录制窗口的程序与尺寸。执行过程中仍保留焦点和尺寸保护。每个脚本使用编号命名的独立文件，保存时先写临时文件，再替换旧文件，避免中途退出损坏脚本。旧版单一文件在首次运行时迁移。脚本文件只允许数据步骤，不执行任意代码。

脚本内容以本地文件保存，MVP 不承诺对文本内容加密。界面须提醒用户在敏感输入前结束录制，并检查已录制步骤。

## 四、实现顺序

1. **桌面框架**：把 HTML Demo 放入 WebView2，打通界面与宿主的消息和状态更新。
2. **窗口与快捷键**：完成目标窗口选择、前台判断、快捷键注册与冲突提示。
3. **录制与回放**：支持全域按键及等待时间，停止并命名保存；旧鼠标步骤继续回放，执行保留失焦保护。
4. **编辑与保存**：完成实时步骤与等待列表、结束录制后的命名确认保存、编辑自动保存、多脚本库、JSON 读写及迁移。
5. **执行工作区**：完成每脚本的执行方式、次数、轮次间隔与快捷键自动保存，以及只读步骤列表和执行高亮。
6. **打包与验收**：生成 Windows 独立执行档，检查 WebView2 Runtime 是否可用。

## 五、验证标准

- **自动测试**：覆盖脚本库读写与迁移、命名确认保存及新录制不覆盖旧脚本、步骤与执行设置自动保存、无目标快捷键及按钮开始、跨窗口不中断、按页面分派快捷键与结束、执行方案校验、三种循环模式、每次按下/重复/松开的独立事件、左右修饰键与功能键、首事件及超过 60 秒的间隔、旧版 `Press` 兼容、步骤高亮和停止时释放按键。
- **桌面验收**：在实际 Windows 的普通测试窗口，设置快捷键，通过按钮或快捷键开始与结束录制，跨窗口继续收集按键，检查实时事件与等待列表，命名确认后进入执行页面；再次录制会新增脚本。重启工具并在执行页面切换脚本，验证三种执行模式、实时步骤高亮、轮次进度及快捷键停止。仅编译或启动成功不算功能验证通过；测试必须包含独立进程的窗口，通过真实 SendInput 进入已安装的监听，再检查界面步骤；这验证 Windows 输入链路，仍不等同于硬件按键或受保护游戏的验收。
- **异常验收**：验证未指定窗口也能录制、空录制不保存、名称为空或过长、保存失败保留内容及重试、明确确认放弃、目标程序或尺寸不符、窗口失焦、窗口关闭、尺寸变化、快捷键冲突、脚本损坏及回放中停止。未完成的实际 Windows 操作测试必须明确记录，不得视为验收通过。
- **兼容性检查**：检查不同缩放比例与多显示器下的坐标；分别验证普通按键、组合键和旧文本步骤。

## 六、已知限制与后续方向

坐标步骤依赖窗口内容布局，界面变化后可能需要重新录制。Windows 模拟输入受权限级别限制，普通权限 FlowKey 不能保证访问管理员窗口。发布执行档的 manifest 使用 requireAdministrator、uiAccess=false，双击时由 Windows 请求授权；取消不会启动。保留源码测试宿主的显式管理员重启入口，通过 Windows runas 请求授权，不设置 uiAccess 或更改系统安全策略。目标进程仅使用 QUERY_LIMITED_INFORMATION 和 TOKEN_QUERY 读取提升状态，避免全访问查询被拒而误判。录制／待命名期间禁止重启，保存失败时保留原窗口；UAC 取消或启动失败也保留原窗口。后续可评估 UI Automation 控件定位、中文输入自动识别和条件执行。
